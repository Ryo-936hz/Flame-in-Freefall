## Contenido y correcciones de integración

Contrato 1.1: segmentos con `sequence`, `Observation.segment_id`, geometría/cara y
O₂ inicial/final del ensayo. OpenAPI/TypeScript generados y ejemplo sintético.
Se corrigieron los dos huecos detectados por P3 antes de publicar:

- Las tres condiciones de O₂ validan 0–100 % inclusive, también en RankingRequest.
- ConditionSegment rechaza extremos inicial/final del ensayo, incluso ausentes.

Se añadieron 23 pruebas de límites, ámbito, compatibilidad 1.0, secuencias con huecos
y observaciones sin asignación. La regeneración no alteró OpenAPI/TS respecto de P1:
las correcciones afectan validadores ejecutables, no la estructura de los modelos.

## Verificación local ejecutada

137 pruebas Python aprobadas; 1 omitida (PostgreSQL sin servidor local), 46 de las
aprobadas son de contrato. Ruff, OpenAPI/TypeScript, tipado, 6 pruebas cliente,
build y HTTP/SQLite con reinicio aprobados. Aviso Starlette/httpx existente.
Modo demo sin credenciales; no se realizaron llamadas a proveedores externos.

Se verificó en worktree separado de raul, con PYTHONPATH apuntando al nuevo código
y dependencias existentes de los mismos lockfiles; se comprobó ROOT para evitar
ejecutar accidentalmente ciencia de raul. No es una nueva instalación limpia.
La comprobación remota PostgreSQL está definida en CI; su resultado se consulta
en Actions y no se presupone a partir de esta ejecución local.

Desde un clon configurado, reproducir con `./scripts/check.ps1`. El script incluye
Ruff, pytest, deriva de contratos, pruebas cliente, tipado/build y HTTP con reinicio.

## Incorporación por el equipo

Conservar la rama de trabajo de cada persona y guardar antes sus cambios pendientes.
Desde esa rama, ejecutar:

```powershell
git status
git fetch origin
git merge origin/main
.\scripts\check.ps1
```

Si aparece un conflicto, combinar ambos comportamientos y revisar el contrato;
no resolverlo aceptando todo un lado ni generar tipos manualmente. Quien tenga
un clon nuevo puede seguir TEAM_START y después incorporar main a su rama.

## Pendientes separados de esta entrega

- La ciencia completa de segmentos de P3 está en `raul` (`8134b1c`); este merge
  publica la base P1, no incorpora toda la ciencia ni su evaluación.
- La ampliación P2 `lujan` usa un esquema alternativo (`condition_stages` /
  `condition_id`) y requiere adaptación antes de integrarse. Número de caras e
  identidad de cara no se intercambian automáticamente.
- IA y frontend de las otras ramas necesitan revisión y posterior integración.
- Los datos de demostración siguen siendo sintéticos; este contrato no valida
  las mediciones ni la comparabilidad de los estudios NASA.

No se modifican la referencia congelada team-start-v1, sus etiquetas ni ramas de
compañeros. Revisar los cambios de validación antes de importar bundles previamente
aceptados con O₂ fuera de rango o extremos indebidamente declarados en segmentos.
